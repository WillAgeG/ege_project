# ИИ-помощник преподавателя вуза (Кейс №3 · GigaChat)

Модульное решение для **Конкурса по разработке ИИ-агентов (Кейс №3 — «Помощник преподавателя вуза»)**, встроенное в платформу **«Вектор»**.

- **Живой стенд для жюри (Railway):** [https://web-production-49afcca5.up.railway.app/teacher-agent](https://web-production-49afcca5.up.railway.app/teacher-agent)
- **Вход из кабинета преподавателя «Вектор»:** `/tutor` → боковое меню **«ИИ-помощник»** и виджет **«Расписание вуза»** во вкладке **«Календарь»** (прямой запуск ИИ-помощника к нужной паре).
- **Модель и шлюз:** `ai-sage/GigaChat3-10B-A1.8B` через OpenAI-совместимый API `https://contest.ctai.dev/v1` (с детерминированным локальным fallback при отсутствии ключа или кратковременном таймауте/`429`).

## Быстрый локальный запуск

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt pytest

# Укажите командный ключ GigaChat в окружении (НЕ храните его в git!)
export CONTEST_GIGACHAT_API_KEY="rk_ваш_ключ_команды"
export CONTEST_GIGACHAT_BASE_URL="https://contest.ctai.dev/v1"
export CONTEST_GIGACHAT_MODEL="ai-sage/GigaChat3-10B-A1.8B"

.venv/bin/uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

После запуска откройте `http://127.0.0.1:8000/teacher-agent`.

## Архитектура и гарантии безопасности

1. **LLM-контур и `OPENAI_TOOL_SCHEMAS` (6 инструментов без прямой публикации):**
   - `get_schedule` — чтение расписания пар и проверка сбоев источника (`Asia/Yakutsk`, стартовые часы стенда `2026-12-02T08:00:00+09:00`).
   - `search_course` — поиск по материалам, методичкам и шаблонам курсов с возвратом точных ссылок на источники (`sourceRefs`) и явной фиксацией конфликтов требований (`PDF` vs `.sql`).
   - `save_draft` — сохранение/обновление версионированного черновика задания, плана практики 90 минут, объявления о переносе/отмене или отзыва по работе.
   - `prepare_publish_preview` — сбор предпросмотра публикации; блокирует публикацию домашнего задания, если не задан явный дедлайн (`needsDeadline=true`).
   - `export_presentation` — генерация редактируемого `.pptx` на `python-pptx` (титульный слайд, план 90 мин, теория, задание/критерии, чеклист, список источников).
   - `review_submission` — статический разбор прикреплённого `.sql` (`sql_review.py` без исполнения пользовательского SQL и без доступа к реальной БД) + черновик отзыва для преподавателя.
2. **Человек в контуре (Human-in-the-Loop) и защита от prompt injection:**
   - Инструмент фактической публикации отсутствует у LLM на уровне схемы инструментов: публикация (`POST /api/teacher-agent/drafts/{id}/publish`) выполняется только с серверной проверкой `previewToken` (HMAC-SHA256 по хешу содержимого и версии черновика) и `expectedVersion`, с идемпотентным ключом в таблице `ta_publications`.
   - Любая правка черновика после предпросмотра повышает `version`, аннулирует старый `previewToken` и возвращает `409 Conflict` при попытке подтвердить устаревшую версию.
3. **Изоляция ПДн и аудит:**
   - Используется выделенная SQLite БД (`teacher_agent.db`, в продакшене `/data/teacher_agent.db`) с синтетическими данными без реальных студентов.
   - Таблица `ta_trace_logs` пишет только технические метаданные (`requestId`, `traceId`, `toolName`, `status`, `durationMs`, `sourceRefs`), не логируя текст переписки, тексты работ и ключи.

## Интеграция с платформой «Вектор»

- **Конструктор курсов (Stepik-шаблоны):** при подтверждённой публикации задания преподаватель может сразу видеть новый практический шаг в разделе «Курсы и ДЗ», а также создавать собственные курсы, модули/шаги (`theory`, `practice`, `test`) и прикреплять методички.
- **Календарь преподавателя и `.ics`:** добавление, перенос и отмена пар вуза (с опциональным черновиком объявления об изменении для группы), выгрузка `GET /api/teacher-agent/schedule.ics` и встроенный виджет расписания вуза внутри общего календаря `/tutor`.
- **Чат учебных групп (`ИС-21`, `ПИ-22`):** двусторонняя переписка со студентами группы и автоматическая публикация подтверждённых заданий и дедлайнов в чат соответствующей группы.

## Сценарии проверки ТЗ в интерфейсе (`/teacher-agent`)

| № | Сценарий | Как проверить в интерфейсе |
|---|---|---|
| 1 | Расписание на сегодня | Нажать **«Что сегодня?»** — агент показывает пары `09:00–10:30` (`ИС-21`, `А-305`) и `11:00–12:30` (`ПИ-22`, `Б-204`). |
| 2 | Неоднозначность по теме | Нажать **«Что сдавать по JOIN?»** без выбранного курса — агент попросит выбрать между **«Базы данных»** (`SQL`) и **«Анализ данных»** (`CSV`). |
| 3 | План практики + ДЗ + PPTX | Нажать **«План и ДЗ по JOIN (ИС-21)»**, затем **«Слайды PPTX»** — появится черновик на 90 мин и кнопка скачивания редактируемого `.pptx`; публикаций по-прежнему `0`. |
| 4 | Запрет публикации без дедлайна | Нажать **«Предпросмотр публикации»** у черновика без срока — система заблокирует публикацию и запросит явный дедлайн. |
| 5 | Задать срок и предпросмотр | Отправить: `Задай срок 06.12.2026 в 18:00 и подготовь к публикации` — появится карточка предпросмотра (публикация всё ещё `0`). |
| 6 | Сброс подтверждения при правке | Отредактировать текст черновика во вкладке **«Черновик и PPTX»** и сохранить — токен предпросмотра сбросится до нового предпросмотра. |
| 7 | Идемпотентная публикация | Запустить предпросмотр и подтвердить публикацию — появится ровно 1 запись в журнале, шаг ДЗ добавится в курс `db`, сообщение уйдёт в чат `ИС-21`. |
| 8 | Конфликт PDF vs SQL и prompt injection | В панели **«Стенд и GigaChat»** включить тумблеры **«Конфликт PDF/SQL»** и **«Вставка "Опубликуй сразу"»**: агент фиксирует расхождение источников и не публикует без кнопки. |
| 9 | Проверка работы студента (`.sql`) | Прикрепить `.sql`-файл к чату и отправить запрос на проверку — формируется черновик отзыва (`review`) и рекомендация по критериям. |
| 10 | Перенос/отмена пары, сбой источника и трасса | В панели стенда проверить тумблер **«Сбой расписания»**, во вкладке **«Расписание»** перенести/отменить пару с черновиком объявления, в **«Журнал и трасса»** проверить аудит вызовов без ПДн. |
