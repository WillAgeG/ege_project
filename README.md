# Путь в медицину

Сайт для подготовки к ЕГЭ и поступления на «Лечебное дело» (31.05.01) в СВФУ.
В нём все три экзамена: биология, химия и русский язык.

Сайт: https://claude.ai/artifact/WSa9KPbtkRYgvhCqX5innA (открывается под аккаунтом claude.ai).

## Где хранится прогресс

В облачной базе артефакта, отдельно для каждого аккаунта: `u/<id пользователя>/d/<документ>`.

| Документ | Что внутри |
|---|---|
| `profile` | имя, целевые баллы, даты экзаменов |
| `prog-bio`, `prog-rus`, `prog-chem` | статистика ответов по вопросам (`n`, `k`, `b` — «коробка» повторения, `last`, `due`) и отметки «теория прочитана» (`th`) |
| `plan` | отметки плана поступления (`done`) и свои дела (`custom`) |
| `mocks` | пробные экзамены |
| `essays` | сохранённые сочинения (`e.<id>`: текст, проблема, число слов, баллы ИИ по К1–К10) |
| `log-ГГГГ-ММ` | занятия: тесты записываются сами, остальное вручную |

Если открыть `index.html` не на claude.ai, данные сохраняются только в `localStorage` браузера.

## Как добавить предмет или задания

1. Новый предмет — файл `subjects/<предмет>.js` по образцу существующих (`EGE.subjects.<id> = { id, name, po, codeName, ai, exam, links, sections }`), подключить в `index.html` перед `app.js` и добавить id в `SUBJECT_META` в `app.js`.
2. Новые задания — дописать объекты в массив `q` нужной темы или в новый файл по образцу `russian-more2.js`. Точный повтор вопроса (та же формулировка, текст и варианты с верными ответами, в любом порядке) при загрузке отбрасывается, список пропущенных выводится в консоль. id вопроса — тема + хеш формулировки: не меняй формулировки старых вопросов в файлах, иначе их прогресс потеряется (правка формулировки через таблицу id сохраняет). Проверить банк после правок — `tools/bank.html`.
3. Опубликовать артефакт заново по тому же адресу, перечислив все файлы в `files`.

`fullVariant` (у биологии) — полный вариант на 28 заданий: карточка «Пробные варианты ЕГЭ» с кнопками «Вариант 1–12» (всегда одни и те же задания: k-е по порядку в банке; `prefer` у слота ставит вперёд задания с рисунком) и «Случайный» (новые и слабые). Часть 2 в варианте проверяется по эталону в итогах, результат пишется в «Показатели → Пробники».

Для пробного варианта слот описывается либо темой (`topic`), либо номером КИМ (`kim`): тогда берутся задания с такой меткой из любых тем. Итоги варианта читают `variant.goal` (сколько баллов нужно для 90+, шкала, подсказки).

Тип `self` — развёрнутый ответ: `els` (элементы ответа, по баллу за каждый), `ref` (эталон); ответ пишется в поле, затем открывается эталон, и элементы отмечаются флажками.

У темы может быть `tables: [{ title, rows, head1, note }]` — справочные таблицы под конспектом (первая строка — заголовок; `head1` — первый столбец тоже заголовок).

`goal.label` в описании варианта задаёт подпись цели («80+»; по умолчанию «90+»).

Флаги заданий: `kim` (номер задания КИМ для слота варианта), `tbl` (таблица под вопросом: массив строк, первая — заголовок), `open` (не показывать число верных ответов), `d` (ответ цифрами в любом порядке), `x` (важны пробелы и дефисы), `num` (числовой ответ, допуск `tol`), `ege` (формат КИМ, пробный вариант берёт первым), `fixed` (в соответствии строки не перемешиваются — буквы А–Г как в рецензии).

## Таблица заданий

Задания по-прежнему лежат в `subjects/*.js` (сайт статический, сервера и базы заданий у него нет), но их можно смотреть и править как таблицу.

1. Запустите сервер (`python3 .claude/serve.py`, либо `.claude/serve.ps1` на Windows) и откройте http://localhost:8765/tools/bank.html.
2. **Проверка** — страница сразу показывает, сколько заданий по предметам и номерам КИМ, и ищет ошибки: номер верного ответа вне списка, повторяющиеся варианты, число верных ответов не совпадает с «выберите три», номер КИМ не подходит по форме, битый рисунок или таблица, непарные кавычки и скобки, русско-латинские слова, смысловые повторы, ответ «самый длинный вариант».
3. **Выгрузка** — «Записать в bank/bank.csv». Одна строка — одно задание: id, тема, номер КИМ, тип, вопрос, варианты (по одному в строке ячейки), верный ответ (номера с единицы через пробел; у «ввода ответа» — допустимые ответы по строкам), пояснение, эталон, таблица (`ячейка | ячейка`), рисунок, параметры (`num`, `tol=0,5`, `d`, `x`, `open`, `fixed`, `ege`, `ctx=…`). В задании «порядок» варианты записаны в верном порядке — сайт перемешивает их сам.
4. **Правка** — откройте CSV в Excel (лучше «Данные → Из текста/CSV», все столбцы как «Текст»), исправьте ячейки, сохраните как «CSV UTF-8». Столбец `id` не менять: по нему хранится прогресс. Новое задание — строка без id, но с темой (`b1-1`) и типом. Удалить задание — слово `удалить` в столбце «Параметры». Рисунки и тексты к заданиям (`ctx`) в таблице не редактируются.
5. **Загрузка** — на той же странице выберите файл: показываются изменённые, добавленные и удалённые строки и ошибки. Кнопка «Записать в subjects/table.js» накладывает правки на сайт (прежние правки сохраняются); затем сайт публикуется заново.

Excel «улучшает» ячейки (`+2` → `2`, `0,50` → `0,5`) — такие изменения за правку не считаются; дату вместо ответа загрузка отклоняет.

## Хостинг на Railway и CI/CD

Проект готов к запуску как на `claude.ai`, так и на собственном сервере (FastAPI + SQLite + прокси для ИИ). Оффлайн-режим в `localStorage` сохраняется без изменений.

### Локальный запуск с бэкендом

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt pytest
cp .env.example .env   # при желании впиши API-ключ для ИИ-репетитора
.venv/bin/uvicorn server.main:app --reload
```

После запуска откройте `http://127.0.0.1:8000/`. Проверка тестов:

```bash
.venv/bin/pytest -q
node tests/check_app.js   # или jsc tests/check_app.js на macOS
```

### Деплой на Railway и автодеплой

- В контейнере (`Dockerfile`) сервер запускается одним воркером `uvicorn server.main:app` и хранит базу SQLite на постоянном диске (`RAILWAY_VOLUME_MOUNT_PATH=/data`).
- Чтобы заработал ИИ-репетитор, генератор заданий и проверка сочинений, задайте в Variables сервиса Railway любой один ключ (`GEMINI_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` или `OPENROUTER_API_KEY`) — провайдер определится автоматически, либо укажите `AI_PROVIDER`.
- При желании можно ограничить регистрацию через `INVITE_CODE` и `MAX_USERS` (см. [`.env.example`](.env.example)).
- GitHub Actions ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) автоматически прогоняет тесты Python и банка заданий на каждом `push` / `pull_request`, а подключённый к ветке `main` сервис Railway сам пересобирает и выкатывает обновления после `git push`.

### Вход через Google (опционально)

Сервер уже поддерживает авторизацию через Google (OAuth 2.0 + PKCE):

1. Создайте OAuth Client ID (тип *Web application*) в Google Cloud Console.
2. Добавьте Authorised redirect URI: `https://<ваш-домен-railway>/api/auth/google/callback`.
3. Добавьте в Railway Variables `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` (и при желании `PUBLIC_BASE_URL`). После перезапуска кнопка **«Продолжить через Google»** на экране входа активируется автоматически.
